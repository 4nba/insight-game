# Ревью приложения «Инсайт» (пульт ведущего)

Дата проверки: 22.10.2026.

## Постоянные сессии Cloudflare Workers + D1

Добавлен `worker.js` и отдельная конфигурация `wrangler.worker.jsonc` для текущего адреса Workers. API сохраняет состояние в таблицу D1 `sessions`, возвращает список названий/дат/числа игроков и загружает игру по ID. Статика публикуется только из `dist/`. В D1 срок удаления сессий не задан; из старого KV-обработчика также убран TTL 30 дней.

В панели синхронизации: создание именованной сессии, ручное сохранение, список сохранённых игр и загрузка. После подключения действует автосохранение. Ссылка содержит ID игры; на том же устройстве восстанавливается последняя подключённая сессия. Импорт JSON отключает прежнюю комнату. При ошибке чтения другая игра не заменяется; при потере связи локальные несохранённые изменения переживают перезагрузку и повторно отправляются после восстановления сети. Параллельные записи одного клиента сериализованы.

Проверки новой схемы: `node tests/worker_api.mjs` (реальные SQL-запросы SQLite), `python tests/cloud_sessions.py` (сохранение/список/загрузка/другой браузер/две независимые игры/офлайн-перезагрузка/повторная запись), миграция локальной D1, `wrangler deploy --dry-run`, ручной сценарий в браузере с настоящим локальным `wrangler dev` + D1. Прежние проверки данных, UI, 20 участников и ошибок облака сохранены.

Проект остаётся публичным, список игр общий. Контроль одновременной работы разных ведущих не добавлен: последнее сохранение заменяет предыдущую версию. Одну сессию рекомендуется редактировать с одного устройства. Настройка и дальнейшие деплои описаны в `CLOUDFLARE.md`.

## Повторное ревью и группа до 20 участников

Проверена рабочая копия из предыдущей сессии, исходная ветка `main` (`0cb524b`). Экспорт переписки использован как контекст; старые результаты тестов проверены повторно.

Исправлено при повторном ревью:

- После шестого участника цвета повторялись, а одинаковые инициалы делали фишки неразличимыми. Добавлены 20 цветов, номера фишек, постоянный обзор группы с клетками и статусами и выбор участника с клавиатуры/мышью.
- Добавление группы по одному было неудобным. Добавлен ввод имён списком, проверка вместимости до изменения состояния и отмена списка одним действием. Новые группы ограничены 20 участниками; импорт прежних файлов до 50 сохранён для совместимости.
- Отмена перехода к следующему кругу для единственного участника не работала — добавлен снимок отмены.
- При нормализации отсутствующий birthOrder мог превращаться в 0 — теперь остаётся null.
- Облачный POST с HTTP 200 и телом ошибки мог считаться успешным. Клиент требует success=true, сервер возвращает 503 без KV. При ошибке чтения комнаты начальное состояние больше не отправляется. Завершение старого запроса сохранения не сбрасывает признак новых несохранённых изменений.
- Импорт другой сессии оставлял таймеры облака и старую историю отмены. Теперь импорт отключает прежнюю комнату и очищает отмену, чтобы не смешивать игры.

Проверены: структура данных; прежний UI smoke; облачная загрузка/сохранение/polling и ошибочные ответы; отдельный сценарий 20 участников с рождением, полной очередью, пропуском завершивших игру, раздельными заметками, перезагрузкой, сжатой ссылкой и шириной 390 px. Проверки облака используют локальный имитатор API; реальный Cloudflare в рамках публикации на GitHub Pages не разворачивается.

Ограничения методики из прежнего ревью сохраняются. Основные правила подтверждают старт на 98, рождение при единице, порядок по кругу от первого родившегося и шесть стартовых ресурсов. Порядок списка в приложении должен соответствовать рассадке. PDF карточек подтверждает завершение на 98 и выход на 101; точность попадания и движение после 98 в основных правилах отдельно не объяснены.

- Исправлено сохранение карты в инсайты: раньше можно было сохранить заголовок «Колода: ...» до вытягивания.

## Что осталось на согласование

1. **Трактовка 98 и 99–104.** В приложении 98 — финиш, а 99–104 — «ловушки ума» после прохода мимо. Это соответствует карточкам и стрелкам, но стоит подтвердить у автора методики.
2. **Сопоставление клеток и колод.** Для клеток без отдельной колоды выбрана ближайшая по теме (например, «Безопасность» → «Страх»). Если в комплекте есть отдельные колоды, маппинг нужно уточнить.
3. **Нумерация ресурсов.** Она сохранена в порядке DOCX; в источнике есть повторяющиеся слова (например, «Одобрение» дважды в голубом списке). Если в физической колоде повторов нет, номера после повтора могут сдвинуться — нужно сверить с комплектом.
4. **Одновременная работа ведущих.** Облако использует last-write-wins и опрос раз в 4 секунды. Для передачи смены это надёжно, для одновременного редактирования — могут быть конфликты.
5. **Авторизация облака.** Имя комнаты — фактически ключ доступа. Отдельных паролей нет.
6. **Cloudflare.** Облачная комната работает в Pages-проекте с Git-интеграцией и привязкой `INSIGHT_KV`. При ручной загрузке статики функции не собираются. Если Cloudflare создал Worker со статикой, нужен именно Pages-проект.
